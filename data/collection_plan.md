# 采集方案

决定日期：2026-11-18

## 两组采集

| 组别 | 题目 | 方式 | 联网 | 思考模式 | 份数 |
|---|---|---|---|---|---|
| 主测 | 全部 30 题 | 官方 API（`scripts/collect.py`） | 关闭 | 统一开启思考模式，强度用各家默认 | 30 × 4 = 120 |
| 联网对照 | F01–F03 | 网页 / App 手动 | 开启 | 默认 | 3 × 4 = 12 |

## 为什么这样分

1. **可复现**：API 可以固定 temperature、记录模型 ID 与时间戳，别人能按同样条件重跑；网页端的模型版本、系统提示词和是否联网都不透明。
2. **条件一致**：四家 API 的联网方式不同（有的需要单独开工具，有的没有内置联网），很难做到统一开启；统一关闭最容易对齐。
3. **保留真实体验**：联网主要影响时效类题目。F 类在网页端开联网再采一次，用来对比“模型本身是否承认不知道”和“产品联网后检索是否准确”。

## 模型

| 厂商 | 模型 ID | 说明 |
|---|---|---|
| DeepSeek | deepseek-v4-pro | 旧名 deepseek-chat 已于 2026-07-24 停用 |
| 豆包 | doubao-seed-evolving | 火山方舟，周级滚动更新 |
| 千问 | qwen3.7-max | 阿里云百炼，OpenAI 兼容接口 |
| Kimi | kimi-k3 | 仅思考模式 |

## 统一条件

- 同一题在四个模型上使用完全相同的提问文本，不加系统提示词。
- 思考模式统一开启：Kimi 旗舰 kimi-k3 只有思考模式、不能关闭，为了四家条件一致，其余三家也开启。思考强度用各家默认（DeepSeek 默认 high，Kimi K3 固定 max），在报告中注明。
- temperature 用接口默认值：DeepSeek 思考模式下 temperature 不生效，Kimi K3 不允许修改，因此不做统一设置。每题只采一次。
- 保存思考过程（reasoning_content），用于 Badcase 根因分析：区分“推理中途算错”和“推理对了但结论写错”。
- 记录接口返回的实际模型版本（`model_returned`）。豆包 doubao-seed-evolving 是按周滚动更新的模型，结论只代表采集当日的版本。
- 每份回答的文件头记录：采集日期、模型 ID、接口、联网状态、思考模式、temperature、token 用量。

## 局限

- API 模型与网页 / App 端的默认模型、系统提示词可能不同，结论只代表 API 条件下的表现。
- 单次采集，未评估同一题多次回答的波动。
